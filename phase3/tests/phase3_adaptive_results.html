1 What Is the Adaptive Strategy?

The Problem

Predictive estimates request cost using max_tokens as worst-case output. But requests typically use only ~35% of their budget on 7B. A request with max_tokens=2048 that generates 500 tokens has 4× overestimated cost — causing unnecessary NACKs and halved throughput.

The Solution

Adaptive learns the actual output ratio via exponential moving average (EMA) from completed requests. Instead of cost = max_tokens, it uses cost = max_tokens × output_ratio. The ratio starts at 1.0 (= predictive) and decays toward the true usage fraction.

// Request lifecycle with adaptive strategy

1. ADMIT: estimated_output = 2048 × 0.35 = 717 tokens // not 2048
2. SERVE: vLLM generates 500 tokens, completes
3. LEARN: sample = 500/2048 = 0.244
    new_ratio = 0.1 × 0.244 + 0.9 × 0.35 = 0.339 // barely moved

// Pressure safety valve

ERROR: vLLM returns 500 (KV exhausted)
    ratio snaps from 0.25 → 0.80 // conservative immediately
    next ~20 completions: ratio gradually learns back down

The sweep parameter is alpha (EMA learning rate): lower alpha = slower learning but more stable, higher alpha = faster adaptation but more volatile.

4 Cross-Model Comparison

When Adaptive Helps
  • Request output varies widely — short requests use 35% of max_tokens, adaptive learns this
  • Bottleneck is not KV-scarce — on 7B, memory bandwidth is the bottleneck, KV cache is abundant
  • Predictive is too conservative — adaptive recovers 10% throughput by correcting the overestimate
  • Test duration is long enough — ratio needs ~23 completions (at α=0.10) to converge
When Adaptive Doesn't Help
  • Requests use full max_tokens — 14B XL generates ~2048 tokens, ratio stays ~1.0
  • KV cache is the bottleneck — cost model is already accurate, nothing to learn
  • Uniform request sizes — no variance for the EMA to exploit
  • Static is sufficient — on 7B, vLLM handles it internally; no external gate needed

5 Infrastructure Lessons

kubectl Context Drift

With multiple EKS clusters, the default kubectl context silently switched to phase4 mid-sweep. First sweep's predictive/adaptive runs actually ran as reactive. Fix: isolated KUBECONFIG=/tmp/phase3-kubeconfig per cluster.

Rollout Restart Required

kubectl set env updates the deployment spec but with maxSurge=0 on a single GPU node, the old pod keeps serving. Fix: kubectl rollout restart after every env change to force pod recreation.

Pipeline Probe Timeout

3 retries × 10s = 30s was too short for model reload (~3 min). Load tests started before vLLM was serving, causing 100% errors. Fix: increased to 18 retries (180s).

Karpenter Node Access Entry

Terraform-created Karpenter node role was missing from EKS access entries. GPU nodes launched but couldn't register with the cluster. Fix: manual aws eks create-access-entry for the Karpenter node role.

6 Interview Takeaway

Adaptive admission control (SGLang new_token_ratio pattern) improves throughput by 10% over static predictive cost models when request output lengths are variable. The EMA-learned output ratio corrects the systematic overestimation that plagues fixed cost models on bandwidth-bound GPUs. However, it provides no benefit when: (a) the cost model is already accurate (14B, KV-scarce), (b) vLLM's internal scheduler is sufficient (7B, static wins), or (c) request sizes are uniform. The key engineering insight is that adaptive vs static cost estimation matters more than which bottleneck metric to gate on.
