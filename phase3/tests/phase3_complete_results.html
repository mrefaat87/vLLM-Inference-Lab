0 Strategy Overview

static Static

RabbitMQ prefetch_count=N is the only gate. No runtime checks. Sweep param: prefetch count (1–20).

reactive Reactive

Checks current system load vs threshold. Rejects if above. Does NOT examine the incoming request. Sweep param: threshold (0.50–0.90).

predictive Predictive

Estimates per-request cost using max_tokens (worst case). Projects post-admission load. Sweep param: threshold (0.50–0.90).

adaptive Adaptive (new)

Like predictive but learns actual output_ratio via EMA from completed requests. Corrects overestimation. Sweep param: alpha (0.01–0.30).

// Adaptive strategy: SGLang new_token_ratio pattern

ADMIT: cost = max_tokens × output_ratio // not max_tokens
LEARN: ratio = α × (actual/max) + (1-α) × ratio // EMA on completion
PRESSURE: vLLM error → ratio snaps to 0.80 // safety valve
CONVERGE: ~23 completions at α=0.10 to reach 90% of true ratio

Key Insights

When external admission control adds value: Three conditions must hold simultaneously: (1) bottleneck resource held for full request lifetime (KV cache), (2) hardware has tight headroom (14B on T4), (3) request sizes vary significantly (20 vs 2048 tokens). When any condition is missing, vLLM's internal scheduler is sufficient.
Adaptive's niche: Adaptive improves over predictive when the cost model overestimates (requests use <100% of max_tokens). On 7B, it recovers 10% throughput. On 14B where the cost model is accurate, it converges toward predictive and adds no value. The strategy's value is workload-dependent, not model-dependent.

Infrastructure Lessons

kubectl Context Drift

Multiple EKS clusters caused silent context switches mid-sweep. Fix: isolated KUBECONFIG per cluster.

Rollout Restart Required

kubectl set env + maxSurge=0 = stale pods. Fix: rollout restart after every env change.

Probe Timeout

3 retries (30s) too short for model reload (~3 min). Fix: 18 retries (180s).

EKS Access Entry

Karpenter node role missing from access entries. GPU nodes launched but couldn't register.

Interview Takeaway

The bottleneck metric matters less than the accuracy of cost modeling. Across 68 configurations, predictive fails on 7B not because it gates on the wrong metric, but because max_tokens overestimates actual output by 3×. Adaptive (SGLang new_token_ratio pattern) fixes this by learning the actual ratio via EMA — recovering 10% throughput on 7B while maintaining the best TPOT of any strategy (34ms). On 14B where the cost model is already accurate, adaptive converges toward predictive. The engineering lesson: adaptive vs static cost estimation is the lever, not which resource to gate on.
