Methodology

How measurements are taken: Each config gets a fresh cold start (GPU nodes deleted, new node provisioned by Karpenter). K8s events provide Scheduled and Pulled timestamps (~1s precision). Worker logs provide WARMUP and READY timestamps (~1s). Pod Ready condition provides readiness timestamp. Exception: +cache-hit reuses the node from +streamer to test compilation cache. Wake-from-sleep keeps the pod running and measures wake latency from worker logs.
Timing precision: Stage boundaries are extracted retroactively from K8s events and worker logs after the pod reaches Ready state. kubectl polling runs every 5s during the wait. All timestamps are UTC epoch seconds with ~1s precision.
